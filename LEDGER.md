# The ledger

One row per strategy, in [LEDGER.csv](LEDGER.csv). Every count this
repository publishes is derived from that file, and that file is
produced by `ledger.py` from the result cards — not typed by hand.

## Why this file exists

On 2026-08-21 an external reviewer read this repository and praised two
scripts as a strength. Both had been discarded days earlier, and the
published counts they supported came from a 571-strategy corpus that had
since grown past 900. Nothing in the repository was lying. The reviewer
simply had no way to tell which artifacts still stood behind which
numbers.

So each number now carries four coordinates: **what** was measured, **by
which code**, **over which corpus**, and **under which set of decisions**.
The last one is the one usually left out.

## Decision epochs

A rule chosen before the data and a rule chosen after it do not carry the
same weight, so they are labelled and never merged. The dates come from
git, not from memory.

| epoch | when the rule was fixed | rules |
|---|---|---|
| E0 | **before the sweep** — CHECKLIST.md, 2026-08-20 15:00 (`4d5a937`) | trade count, expectancy and p-value in both windows; look-ahead |
| E1 | **after the results, because of them** | `recursive-analysis` promoted from *reported* to *excluding* |
| E2 | after, from an outside source | the freqtrade community's backtesting traps |
| E3 | after, from an outside source | trades shorter than their own candle |
| E4 | after, prompted by an external review | Benjamini-Hochberg FDR |

**E1 is the one to be suspicious of, and it is mine.** Both bias
detectors ran on every strategy from the first commit of the harness
(`be77d12`, 2026-08-20 14:42), and both were named in the checklist
published before the sweep. What was *not* fixed in advance was which of
them excludes a strategy from the headline. The published funnel
(`fff3d17`) excluded on look-ahead only. Exclusion on recursion was added
after I saw that the strategies beating buy-and-hold out of sample were
`NOTankAi_15` at +63,645,298% and `NowoIchimoku1hV2`.

That is not a detector invented to kill an inconvenient result — the
detector predates the result by a day. It is a **degree of freedom left
open in the pre-registration and closed after seeing the data**, which is
a smaller sin and still a real one. Both counts are published below, in
the order the decisions were made. E2 and E3 are post-data too, but they
came from documents indifferent to our result; a weaker objection, and
still marked.

## Reading the ladder

Each line is the same population passing one more gate. `G0_measured` is
not a quality filter — it counts the strategies that produced numbers in
both windows at all. The largest single drop is not any bias detector: it
is `G2_is_pos`, strategies whose expectancy is negative in the window
their own author chose.

`G9_candle` **fails a strategy whose trade duration was never measured**
rather than passing it. Cards computed before the duration layer existed
carry no such field, and `not card.get("intracandle")` would have quietly
read as *passed*. Absence of a flag is not absence of the defect.

## What a row does not tell you

That a strategy survives every gate is not a claim that it makes money.
It is a claim that this pipeline could not show that it does not. The last
column of the epoch table — how many survivors beat buy-and-hold on the
same pairs over the same window — is the one that matters, and the one
nearly every published backtest omits.

Survivors under the full rule set: **6**.
